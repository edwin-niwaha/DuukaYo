Authentication that fits your client.

Public browsing is open. Account and merchant operations require authorized access.

MOBILE & API CLIENTS

Bearer tokens

Send your username and password to POST /api/v1/auth/token/. Include Authorization: Bearer <access> with protected requests. Refresh at auth/refresh/ and replace both tokens when rotation returns a new refresh token.

BROWSER CLIENTS

Session + CSRF

First call GET /api/v1/auth/session/ to obtain a CSRF token. Send it as X-CSRFToken with session login and subsequent unsafe requests, and include cookies. Allowed origins are configured by your deployment.

From browsing to checkout.

Choose the flow that matches your customer experience.

Marketplace checkout

Create a cart at carts/, add its product lines with PUT carts/{id}/, request a quote at carts/{id}/quotes/, then submit its quote ID and a UUID client_id to carts/{id}/checkout/. Guest requests must include X-Cart-Token using the token returned on cart creation. Keep that token private. Use the explorer for request fields.

In-store point of sale

Use businesses/{id}/sales/ for sales. Register, shift, stock, return and report endpoints are scoped to a business and its authorized branches. Preserve the original command ID and payload when retrying a submitted sale.

Availability matters. Preview products may appear in discovery with zero orderable availability. Check stock and the latest quote before checkout. A displayed product is not a guarantee of stock.
